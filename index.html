Selected work

VERIDEX: document search that quotes its sources

The problem
Every reading tool built on a language model can invent a citation, and one fabricated quote makes the whole tool worthless to a lawyer, a student or a technical team.
What I built
An offline-first engine in Python that takes PDF, text, Markdown and code, answers with verbatim source spans, and re-reads every quote from the source bytes before printing it. The default path sends zero tokens to any model. Accounts, scrypt password digests, single-use invitation codes, HttpOnly sessions, per-address login throttling and an audit trail over permission changes. An optional model tier can only point at a unit id, and the API re-verifies the evidence before it can surface as a citation.
Why it is hard
Determinism, plus a sandbox for model-written Python with no sockets, no subprocesses, no writes outside its work directory, and hard time, memory and byte caps.
Evidence
README plus tests per module: engine, routes, model tier, sandbox, scoping, transport.

cbticks: reading a game's own rules off the wire

The problem
A hit-timing tool that hardcodes numbers is wrong the moment the client updates, and the 1.8.9 Minecraft client is obfuscated, so nothing can be matched by class name.
What I built
A Java agent injected with -javaagent that hooks only the pipeline mutation points, the Netty encoder and decoder, and the frame swap, and reads packet ids out of the buffer itself. Verdicts come from the client's real damage window: PERFECT, LATE, REFUSED, OPEN, NO_TARGET, WHIFF, each explained on screen, with a banner shown exactly while the window is open.
Why it is hard
Instrumentation without touching game classes, a shaded agent for Java 8, a hand-rolled bitmap font in an LWJGL overlay, and signals that swallow every throwable so the agent can never crash the game.
Evidence
README with the packet path it hooks and the verdict table it derives.

External black-box penetration test of a compromised game server

The problem
A live game server had been breached and the owner needed the entry vector, not a scanner dump.
What I did
Authorized audit from outside: full TCP range and about 75 UDP ports, TLS 1.0 to 1.3, nuclei with over 10,000 template requests, ffuf over about 600 paths and 70 API endpoints, request smuggling checks, host header injection, subdomain enumeration, certificate transparency, domain history drift, GitHub secret search, and static analysis of two leaked repositories.
What the report says that most reports do not
The web surface was tight. The likeliest vectors were a team member's GitHub account, SSH password authentication on an operating system past standard support, and a recent registrar change. We confirmed active SSH protection by watching our own address get dropped while the web stayed up. Overall risk: medium to high, and the application was not the problem.
Evidence
Executive summary, findings sorted by severity, and a methodology table with tool versions and the negative results included.

Two more tools worth mentioning: a Manifest V3 browser extension with 286 passing tests that writes proposals into a live page and refuses to claim a success it cannot observe, and a self-binding system for Windows and Android that ships with a written model of what it does not stop.
